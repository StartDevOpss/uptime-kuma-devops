# Security Policy

## Secret Management

All sensitive credentials in this project are managed via **GitHub Actions Secrets** and are never stored in the codebase.

| Secret | Description |
|---|---|
| `KUBECONFIG` | Kubernetes cluster credentials used during CI/CD deploy |
| `GITHUB_TOKEN` | Auto-generated by GitHub Actions — scoped per workflow run |

## What is safe to be public

- All Kubernetes manifests (`k8s/`) contain no sensitive data
- The `Dockerfile` uses the official upstream image with no embedded credentials
- No API keys, passwords, or tokens are hardcoded anywhere in this repository

## Reporting a Vulnerability

If you find a security issue in this project, please open a private GitHub issue or reach out directly via [LinkedIn](https://www.linkedin.com/in/gabrieldevops).

## Best Practices adopted

- Secrets injected at runtime via GitHub Actions environment
- Least privilege: `GITHUB_TOKEN` scoped to `packages: write` and `contents: read` only
- Images tagged with commit SHA to ensure traceability of every deploy
